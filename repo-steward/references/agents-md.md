# AGENTS.md 维护钩子模板

`AGENTS.md` 是项目根部的持久记忆文件，只记录**维护钩子**与**影响维护的例外**。本 skill 做的是维护工作，不是项目清单或检查工作；`AGENTS.md` 不是项目说明书、结构清单或检查报告。

## 唯一准则

**有则加操作，异则加备注，无则什么也不加。**

- **有**：存在需要持久执行的维护钩子 → 追加一条“触发 → 同步动作”。
- **异**：存在影响维护操作的例外（如“本项目不设 docs，README 即事实源”）→ 追加一行备注。
- **无**：没有新钩子，也没有影响维护的例外 → 本轮不追加。

## 不写入的内容

- 项目介绍、定位、受众、徽章。
- 目录结构清单，以及非标准目录名。例如源码不是 `src/` 而是自定义名称平铺 → **不写**。
- 构建/测试命令、环境要求、红线，除非它们本身就是某条维护动作。
- 本次盘点的结果、skill 的判断过程、一次性操作日志。

## 写入规则

- **增量追加**：只读现有内容，在末尾追加；不重写、不删除、不重排。
- **修正方式**：旧条目有问题时，追加一条带日期与原因的「修订」记录，保留原文。
- **克制追加**：每轮 loop 都可能追加，必须控制体积：
  - 追加前查重，已有条目能覆盖的不重复写。
  - 优先写通用钩子（按变化类别），不写一次一事的细碎记录。
  - 没有新增维护义务时不追加。

## 文件形态

整个文件只由一个大标题、一张钩子表、若干备注组成：

```markdown
# 维护钩子

| 触发 | 同步动作 |
| --- | --- |
| 功能新增 / 行为变更 | 更新 `CHANGELOG.md` 未发布段；README 三模块；`docs/architecture.md` 或 `docs/design.md`；`tests/` 对应样例 |
| CLI / 参数 / API / JSON Schema 变更 | 更新 `docs/reference.md` |
| 构建 / 测试流程变更 | 更新 `docs/development.md` |
| 依赖 / 第三方代码 / 资源变更 | 更新 `THIRD_PARTY_NOTICES` |
| 版本发布（tag） | 归档 `CHANGELOG.md`；生成 Release 文案 |
| 根目录入口文件/目录或资产位置变更 | 更新 README 结构说明（如有）、本文件、workflow 路径 |
| workflow 新增 / 触发变更 | 更新本文件 workflow 地图；`docs/development.md` |
| `tests/` 结构或样例变更 | 更新本文件 tests 约定；`test.yml` 路径 |

## 备注

- 不设 docs/：README 即事实源。
```

备注只在“异”时出现；没有例外就省略整个备注节。

## 钩子写法

- 一条钩子 = 一个触发 + 一组同步动作。
- 触发写“变化类别”，不写具体功能名，避免每轮追加。
- 动作写文件路径或命令，不写“更新文档”这种模糊表述。
- 若项目含 agent skill，且内容以 skill reference 为 canonical，钩子中直接指向该 reference。

## 备注写法

- 只写影响维护操作的例外，不写结构差异。
- 每条一行，不解释。
- 没有例外就不写。
